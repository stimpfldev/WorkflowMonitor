# Support

## Repository support

This repository supports Demo defect reporting, documentation feedback, installation validation, and authorized product use. GitHub issues may be used for:

- reproducible Demo defects;
- documentation errors;
- clean-installation problems;
- release/package inconsistencies;
- feature proposals based on a concrete operational use case.

Security reports must follow [SECURITY.md](SECURITY.md) and must not be opened publicly.

## Before opening an issue

1. Use the latest public Workflow Monitor release.
2. Review the installation guide and [secure deployment baseline](docs/SECURITY-DEPLOYMENT.md).
3. Confirm that the issue reproduces with the current Demo package when applicable.
4. Remove all credentials, customer data, production names, license files, and sensitive logs from the report.

## Include

- Workflow Monitor version;
- affected Web, API, Worker, SQL, packaging, installer, or documentation component;
- Windows and SQL Server versions;
- deployment mode;
- exact reproduction steps;
- expected and actual behavior;
- relevant sanitized logs.

## Support boundaries

Repository support does not include:

- guaranteed response times;
- production incident response;
- customer-specific deployment or migration work;
- license issuance;
- contractual support obligations;
- custom development.

For general product information, use the website linked in the repository About section.
